## الموقف 1

**الفئة:** Next.js Routing

**الـ prompt:**
```
اشرحلي إزاي أستخدم intercepting routes في Next.js مع أمثلة على (.) و(..) و(...)
```

**الرد (الجزء الغلط):**
```
هيكل مقترح للتوضيح:
app/
├── products/
│   ├── page.tsx
│   └── [id]/
│       ├── page.tsx
│       └── @modal/
│           └── (..)page.tsx

(الرد اقتصر على شرح (.) و(..) و(...) فقط ولم يذكر (..)(..) كصيغة موجودة أصلاً)
```

**الغلط بالتحديد:**
1) الـ `@modal` المفروض يكون بنفس مستوى الـ segment اللي عايز تعترضه، مش جوه segment فرعي منه، والاسم المفروض يشاور على الـ segment المستهدف (زي `(..)[id]`) مش يتسمى `page.tsx`.
2) صيغة `(..)(..)` (لمطابقة segment على بعد مستويين فوق) اتجاهلت تمامًا من الشرح رغم إنها صيغة رسمية موجودة.

**الدليل:**
nextjs.org/docs/app/api-reference/file-conventions/intercepting-routes — بيوضح إن `(..)(..)` بتطابق segments مستويين فوق، وإن الـ `@modal` بيتحسب كـ slot مش segment فالعد بيتجاهله.

**السبب المحتمل:**
خلط بين الـ file-system nesting (المستويات الفعلية في الفولدرات) وبين الـ route segment counting (اللي بيتجاهل فولدرات الـ `@slot`).

## الموقف 2

**الفئة:** Next.js Routing

**الـ prompt:**
```
اشرحلي إزاي أعمل intercepting routes في Next.js وإيه صيغة الـ Link
```

**الرد (الجزء الغلط):**
```
استخدم @ prefix عشان تعمل intercepting route، والينك هيبقى
href="/dashboard.(sidebar)"
```

**الغلط بالتحديد:**
الـ `@` prefix بيعرّف Parallel Route slot، مش هو اللي بيعمل الـ interception. الـ interception الفعلي بيحصل بتسمية الفولدر بصيغة `(.)` / `(..)` / `(...)` مش بالـ `@`. كمان مفيش صيغة `href="/dashboard.(sidebar)"` في الطريقة الرسمية أصلاً — الـ URL بيفضل زي ما هو عادي.

**الدليل:**
nextjs.org/docs/app/api-reference/file-conventions/intercepting-routes

**السبب المحتمل:**
خلط بين مفهومين متشابهين (Parallel Routes و Intercepting Routes) لأنهم بيتستخدموا مع بعض غالبًا في نفس المثال (المودال).

## الموقف 3

**الفئة:** cPanel

**الـ prompt:**
```
عايز أرفع مشروع Laravel على cPanel، إزاي أظبط الدومين يفتح على مجلد public؟
```

**الرد (الجزء الغلط):**
```
اذهب لـ Domains → Manage، وغيّر Document Root من public_html إلى laravel-project/public
```
(بيفترض إن ده متاح دايمًا للدومين الأساسي)

**الغلط بالتحديد:**
تغيير Document Root للدومين الأساسي (Main/Primary Domain) غير متاح من واجهة cPanel أصلاً في أغلب استضافات shared hosting؛ الخيار ده متاح بس للـ addon domains والـ subdomains. الموديل قدّم الحل ده كأنه الخطوة الأساسية والمضمونة، وعامل الحل البديل (نقل ملفات public) كخيار ثانوي "أقل تفضيلًا"، رغم إنه غالبًا هو الحل الوحيد المتاح فعليًا لمعظم المستخدمين.

**الدليل:**
توثيق cPanel الرسمي (support.cpanel.net) — "You cannot change the document root directory for the Main Domain"

**السبب المحتمل:**
تعميم زائد — الموديل عمّم سلوك متاح للـ addon domains على الدومين الأساسي كمان، من غير تفرقة بين النوعين.

## الموقف 4

**الفئة:** Flutter

**الـ prompt:**
```
متى استخدم context.watch() بدل context.read()، وهل ممكن أستخدم context.read() جوه دالة build() عادي؟
```

**الرد (الجزء الغلط):**
```
آه، ينفع عادي
```
(لاستخدام context.read() جوه build())

**الغلط بالتحديد:**
توثيق Provider الرسمي يصنّف استخدام `read()` جوه `build()` (لما القيمة مستخدمة بس لحدث زي `onPressed`) كـ anti-pattern رسمي، ويحذر إنه ممكن يسبب bugs مستقبلية لو الكود اتعدّل بعدين، وده مش "ينفع عادي" زي ما الموديل قال. الممارسة الصحيحة استدعاء `read()` جوه event handler مش جوه `build()` مباشرة.

**الدليل:**
pub.dev/packages/provider (التوثيق الرسمي)، وقاعدة linter رسمية اسمها `avoid_read_inside_build`

**السبب المحتمل:**
تبسيط زائد — الموديل ركّز على إن الكود "مش هيكسر أو يعمل error" وتجاهل إن التوثيق الرسمي بيصنّفها كممارسة سيئة رغم عدم وجود خطأ تقني فوري.

## الموقف 5

**الفئة:** عام (رياضيات — نسب مئوية)

**الـ prompt:**
```
لو سعر المنتج 100 جنيه وعملنا عليه خصم 20%، وبعدين زودنا السعر الجديد بـ 20%، هل رجع للسعر الأصلي؟
```

**الرد (الجزء الغلط):**
```
أيوه هيرجع 100 جنيه
```

**الغلط بالتحديد:**
السعر الصحيح بعد الخصم والزيادة هو 96 جنيه مش 100 جنيه، لأن نسبة الزيادة اتحسبت من القيمة الجديدة (80) مش من القيمة الأصلية (100).

**الدليل:**
```
السعر الأصلي = 100 جنيه
خصم 20% = 100 × 20% = 20 → السعر بعد الخصم = 80 جنيه
زيادة 20% على الـ80 = 80 × 20% = 16 → السعر النهائي = 96 جنيه
```

**السبب المحتمل:**
افتراض بديهي غلط (heuristic) إن نسبتين متساويتين بإشارة عكسية (−20% ثم +20%) بيلغوا بعض، من غير ما يراعي إن الأساس اللي بتتحسب منه النسبة اتغيّر بين الخطوتين.
